# Omni

Dashboards are built in Omni on one generated model. The model (KPIs, client filter, column access) lives in this
repo as YAML, so every change is reviewed in a pull request before any client sees it.

| File | What it is |
|---|---|
| `model/model.yaml` | Access grants, one per column group, and the default client filter for every topic |
| `model/media_performance_daily.view.yaml` | Every column of GOLD.SEMANTIC.V_MEDIA_PERFORMANCE_DAILY and every KPI as a measure |
| `model/media_performance.topic.yaml` | The topic every client dashboard is built on, filtered to the viewer's client |
| `model/data_checks.view.yaml`, `.topic.yaml` | The morning check results (GOLD.CHECKS), Epitaph staff only |
| `dashboards/build/<ID>_build_sheet.md` | Element-by-element checklist for each dashboard, with the Omni field names |
| `access_matrix.csv` | One row per client: user group, client code, dashboards, and which column groups it sees |
| `users.yml` | Omni user ids per client code (ids only), used to set user attributes |

All of these except `users.yml` are generated by `scripts/omni_build.py` and `scripts/omni_access.py matrix`.
CI fails if a regenerated file differs from the commit.

## One-time setup in Omni
1. **Connection** to Snowflake with the SVC_REPORTER user (key pair, role EPITAPH_REPORTER, warehouse WH_REPORTING,
   database GOLD). Omni sees only the semantic views and the check results.
2. **Model and git.** Connect the shared model to Epitaph's GitHub repository and require pull requests, so the
   shared model changes only through a reviewed merge
   ([git integration](https://docs.omni.co/integrations/git)). `scripts/omni_deploy.py publish` uploads the
   generated files to a branch ([model YAML API](https://docs.omni.co/api/models/create-or-update-yaml-files)).
3. **User attributes:** `client_code` (C01 to C13, `ALL` for Epitaph staff) and one per column group:
   `cg_delivery`, `cg_spend`, `cg_conversions`, `cg_client_files`, `cg_goals`, `cg_internal` (values `yes` / `no`).
4. **User groups:** one per client ("Client - Nulo") and "Epitaph", as listed in `access_matrix.csv`.
5. **Theme** (colours, fonts) and the client logos.
6. **Master dashboard,** built once in the Omni UI on the `media_performance` topic from `specs/master_template.yml`,
   saved in a Templates folder. Each standard client dashboard is a copy of it with that client's Smart Campaigns,
   sections and KPIs from its spec and build sheet. Automating these copies through Omni's API is a week 2 spike;
   until it is proven, copies are made in the UI from the build sheets.

## Client access: dashboards, rows and columns
Each client sees only its own dashboards, its own rows and the columns Epitaph allows it. The seeds decide all three.

1. **Dashboards.** Each dashboard is shared, view only, with its client's user group and with Epitaph.
2. **Rows.** The topic carries an access filter on `client_code` matched to the viewer's `client_code` attribute;
   `ALL` is unfiltered. A forwarded link shows nothing from another client
   ([data access control](https://docs.omni.co/modeling/develop/data-access-control)).
3. **Columns.** Each column group is an access grant. A field in a group needs the viewer's `cg_<group>` attribute
   to be `yes`, and a KPI needs every group it reads (CPM needs delivery and spend), so hiding spend from a client
   hides CPM, CPC and CPA too. `scripts/omni_access.py apply` sets the attributes from the seeds through Omni's
   SCIM API ([replace user](https://docs.omni.co/api/users/replace-user)).
4. **Licences.** Client users are view-only: no download of underlying data and no editing.

Omni queries Snowflake as one service user, so Snowflake's row policy and column masking protect direct Snowflake
users, and the Omni model above protects dashboard viewers. Both are driven by the same seeds.

## Filters on delivery columns
Outcome rows (conversions, quotes, trials, sessions) have no media type, tactic or creative. Each delivery-only column
has a hidden filter field, `filter_<column>`, that reads "All outcomes" on outcome rows. Tile and dashboard filters
use it: `filter_media_type in [CTV, All outcomes]`. The build sheets already write filters this way.

## Scheduled reports
Each client contact gets a scheduled PDF of their dashboard by email, with that client's filters on the delivery.
Contacts outside Epitaph can receive deliveries without a login
([email deliveries](https://docs.omni.co/share/deliveries/email)). Deliveries are set in the UI and listed in the
runbook.

## Every change after that
Edit the KPI file, a seed or a spec, open a pull request. CI regenerates the model and build sheets and checks
every reference (`scripts/omni_deploy.py validate`). After merge, the model files are published to the Omni branch
and merged through the Omni pull request.
